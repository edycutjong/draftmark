Line 001 · The reading

One number, read off a moving sea.

A draft survey weighs bulk cargo from the draft marks at six positions: read the waterline, look up displacement in the ship's booklet, subtract ballast, fuel and water. The weak steps are human.

The eyeballed mean

The surveyor picks a mean by eye; the reading is a judgment, not a record.

The per-ship spreadsheet

Every booklet has its own tables and sign conventions; a spreadsheet is hard to check against it line by line.

Line 002 · Measure

SAM 3.1 watches all sixty frames.

Crop the mark column, scale it 2×, and SAM 3.1 segments every painted numeral and the water surface in each frame. Spark 1.3 reads the strings; a label only counts when five code checks agree. On clip eeLL the label chain failed the fit-residual and anchor checks, so DraftMark refused rather than publish a draft.

Line 004 · Certify

Code prints every number. Then it signs them.

No model writes a figure on the certificate. Code assembles it from signed station outputs and ends in a decision: issue, issue with a warning, or refuse.

  1. 004.1
    Each station's output carries an HMAC-SHA256 signature; an edited measurement certifies REFUSE UNSIGNED.
  2. 004.2
    Both real hull clips end in REFUSE OUT_OF_TABLE: 12.761 m and 20.830 m lie outside the only booklet's 0.5–9.3 m table, and the program will not guess.
  3. 004.3
    On the booklet itself it issues with a warning, because all six drafts were typed in, not filmed.

Line 005 · Check

SYNTHETIC

Weighed against a known truth. A rendered one, for now.

The real clips end in refusal, so where is the weight checked? On twelve loads of a barge drawn in code, the waterline set by physics and the swell by us. SAM reads the rendered numerals and Muse Spark their labels, live, but SAM finds no rendered water (0 masks on 12 clips), so the water edge is a colour threshold on our own pixels. This checks the chain, not real water, and the three code fixes it forced were found on these same loads, so it is not a held-out score. There is no physical scale check yet.

What stops it from lying

Generated code never runs in the server process

A static gate, then a no-network sandbox subprocess, JSON in and out. Two escapes, re.enum.sys from our own testing and a format-string walk from architecture review, are regression tests now.

Questions a judge would ask

Q1Isn't this just an image analyzer?
No. It measures a waterline in each of 60 video frames and averages it through the swell with a stated uncertainty. Then an agent writes the ship's program and must prove it against the booklet. Every step can refuse.
Q2What is live and what is recorded?
This page replays recorded runs, each labelled with its run id: dB7X from real SAM and Spark calls, Trieste from Wonder's saved program re-run in the sandbox. In the live app the self-test re-runs; uploading a clip needs a judge code, because each upload spends Meta credit.
Q3Why do both real clips end in REFUSE?
The only booklet we have is the Trieste's, a Ro-Ro/passenger ship whose table covers 0.5–9.3 m. Clip dB7X reads 12.761 m and UKTRQ 20.830 m, so the program raises OutOfTable instead of extrapolating. The measurement stands; the weight is refused.
Q4How do you know Wonder's program is right?
It has to reproduce at least 20 of the booklet's 22 printed conditions within 0.1 % (it reproduces 22), agree with our reference program over 200 random cases (largest difference 0.00007 %), and raise on two out-of-table probes. The printed displacements were never in Wonder's context. Condition 4.1 is one of those 22, and the 200 cases check Wonder's program against our own reference program.
Q5How accurate is the weight?
There is no physical scale check and no real-ship accuracy claim. On the filmed hull the stated figure is repeatability (±0.086 m on dB7X), and a one-pitch label miss would move the draft 0.20 m. On twelve loads of a barge drawn in code, all twelve cargo figures landed within ±2 % of the constructed truth (median 0.12 %, worst 0.75 %), with SAM reading the numerals live but not finding the rendered water, so that edge is a colour-threshold stand-in.
Q6What does a run cost?
The dB7X measurement used two SAM 3.1 video calls and two Spark 1.3 reads: $0.0397 at list prices. Writing the program took three Wonder calls, est $0.481 for the default program (one booklet so far).
